# NimDare — Product Overview

## 1. What is NimDare?

NimDare is a social accountability and skill-challenge platform built around NIM.

Users can create challenges for themselves, challenge friends, or participate in community challenges. Participants can commit NIM to a challenge, complete the challenge, submit proof when required, and receive the outcome or reward according to the challenge rules.

### Core loop

Create a challenge → Commit NIM → Complete the challenge → Prove/verify completion → Receive the outcome/reward

---

## 2. Problem

People often set goals and make commitments but struggle to follow through because there is little accountability, motivation, or consequence.

NimDare aims to make commitments more meaningful by combining social accountability, challenges, verification, and NIM-based incentives.

---

## 3. Target Users

### Individual users

People who want accountability for personal goals.

### Friends

People who want to challenge each other and complete goals together.

### Communities

Groups that want to organize challenges and competitions around shared interests.

---

## 4. Challenge Types

### Solo Challenge

A user creates a challenge for themselves.

### Friend Challenge

A user challenges one or more specific people.

### Community Challenge

A challenge that can be joined by multiple users.

---

## 5. Example Challenges

* Complete 5 coding lessons in 7 days.
* Solve 20 programming problems this week.
* Read one book in 14 days.
* Complete 10 workouts in 30 days.
* Maintain a 7-day learning streak.
* Complete a creative project before a deadline.

---

## 6. Why NIM?

NIM is intended to provide a meaningful incentive and commitment mechanism within NimDare.

NIM should not simply be added as a payment option. It should contribute to the challenge and accountability experience.

---

## 7. Core Product Flow

1. User connects/authenticates.
2. User creates or discovers a challenge.
3. User joins the challenge.
4. User commits the required NIM.
5. User works toward the challenge.
6. User submits proof if required.
7. The challenge result is verified.
8. The challenge is completed.
9. The appropriate NIM outcome/reward is processed.
10. The user's history is updated.

---

## 8. MVP Goal

The MVP should provide a simple but complete challenge experience rather than attempting to build every possible feature.

The priority is:

* Clear user experience
* Working challenges
* Reliable challenge lifecycle
* Meaningful NIM integration
* Basic verification
* Secure transaction handling
* Good design
* A functional end-to-end experience

Features outside the core experience should be postponed until the MVP is stable.
